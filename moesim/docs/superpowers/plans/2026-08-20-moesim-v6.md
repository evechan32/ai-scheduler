# moesim v6 — 排队与重叠感知调度 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox syntax.

**Goal:** 让排队影响与 CPU 资源影响进入调度决策（EFT 范式），并实现预取重叠（PCIe 传输与计算重叠）。

**Architecture:** 资源层暴露队列/利用率/等待查询 → 状态层携带反馈快照 → 新策略 `OverlapAwarePolicy`（EFT 放置 + 带宽门控预取）→ 适配器把 prefetch 排在关键路径之外，跨步用 `pending_loads` 追踪在途传输。

**Tech Stack:** Python>=3.10, numpy（sim/scheduler numpy-only）。

def test_bandwidth_queue_depth_and_wait():
    bw = BandwidthResource(bandwidth_gbps=10.0)  # 100MB => 10ms
    bw.reserve(0.0, 100.0)

    # 两个作业并行，t=5 时完成
    assert comp.wait_time_ms(5.0, 10.0) == 15.0  # 5 + 10 = 15

### Task 44: OverlapAwarePolicy（EFT 放置 + 带宽门控预取）

**Files:**
- Create: `moesim/scheduler/policies/overlap.py`
- Test: `tests/scheduler/test_overlap_policy.py` (new)

**Interfaces:**
- `OverlapAwarePolicy(pcie, gpu_concurrency=1, cpu_concurrency=4, prefetch_n=2,
  max_pcie_queue=2, util_prefetch_threshold=0.7)`
- `decide`：
  1. 驻留专家：GPU 严重排队且 CPU 便宜 → execute_cpu；否则 execute_gpu。
  2. 非驻留：resident 收益（v5）够 → load；否则 EFT 比较：
     `cpu_EFT = cpu_wait_ms + cpu_exec*(1+cpu_queue_len/cpu_concurrency)`
     `gpu_EFT = pcie_wait_ms + transfer_time + gpu_exec*(1+gpu_queue_len/gpu_concurrency)`
     cpu_EFT < gpu_EFT → execute_cpu；否则 load。
  3. 预取：`pcie_queue_len <= max_pcie_queue` 且 `pcie_utilization <= threshold` 时，
     按 activation_freq 取 top-N 非驻留非请求专家，容量允许则 emit `prefetch`。
- 测试：EFT 选 CPU（cpu_wait 小 vs pcie_wait 大）、EFT 选 GPU（CPU 饱和）、
  预取门控（PCIe 拥塞不预取）、驻留稳定性、热专家预取。

- [ ] **Step 3: 实现**
